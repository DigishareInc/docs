Un **modèle de message** est le message qu'une campagne envoie. Vous le créez une fois, puis vous utilisez son `id` comme `message_template_id` quand vous [créez une campagne](/fr/developer-guides/campaigns).

Toutes les requêtes demandent un [jeton Bearer](/fr/developer-guides/authentication). L'entreprise vient de votre jeton.

## 1. Quel appel pour quel canal

| Canal | Appel | Validation Meta | Quand l'utiliser |
| :--- | :--- | :--- | :--- |
| **WhatsApp (modèle)** | `POST /v1/api_provider_message_templates` | **Oui** (quelques minutes à 24 h) | Quand `status` vaut `approved` : Digishare crée alors le modèle de message pour vous |
| **SMS** | `POST /v1/message_templates` | Non | Tout de suite |
| **Telegram** | `POST /v1/message_templates` | Non | Tout de suite |
| **E-mail** | `POST /v1/message_templates` | Non | Tout de suite |

::note
Un **modèle** WhatsApp est le seul message que vous pouvez envoyer à un contact qui ne vous a pas écrit depuis 24 heures. Dans la fenêtre de 24 heures, un message WhatsApp libre (texte, image, boutons) ne demande aucune validation.
::

## 2. WhatsApp : soumettre un modèle à Meta

Vous envoyez le modèle au format de Meta. Digishare le transmet à Meta via votre numéro WhatsApp.

::api-playground
---
method: POST
url: "https://api.digishare.ma/v1/api_provider_message_templates"
headers:
  Authorization: "Bearer VOTRE_TOKEN"
  Content-Type: "application/json"
body:
  channel_code: "whatsapp"
  name: "order_ready"
  external_id: "order_ready"
  status: "submit"
  data:
    name: "order_ready"
    language: "fr"
    category: "UTILITY"
    components:
      - type: "BODY"
        text: "Bonjour {{1}}, votre commande {{2}} est prête."
        example:
          body_text:
            - ["Sara", "A-1042"]
      - type: "FOOTER"
        text: "Atlas Store"
      - type: "BUTTONS"
        buttons:
          - type: "QUICK_REPLY"
            text: "Merci"
responseSample:
  data:
    object: "ApiProviderMessageTemplate"
    id: "apmt_x7k2p9"
    api_provider_instant_id: "ID_DE_VOTRE_NUMERO_WHATSAPP"
    external_id: "order_ready"
    channel_code: "whatsapp"
    name: "order_ready"
    status: "submitted"
    data:
      name: "order_ready"
      language: "fr"
      category: "UTILITY"
---
::

### Champs du corps

| Champ | Type | Requis | Description |
| :--- | :--- | :--- | :--- |
| `channel_code` | String | **Oui** | Toujours `whatsapp`. |
| `name` | String | **Oui** | Nom du modèle : lettres minuscules, chiffres et `_` uniquement. |
| `external_id` | String | **Oui** | Même valeur que `name`. |
| `status` | String | **Oui** | `submit` l'envoie à Meta tout de suite. `draft` l'enregistre seulement. |
| `data.name` | String | **Oui** | Même valeur que `name`. |
| `data.language` | String | **Oui** | Code de langue, par exemple `fr`, `en`, `ar`. |
| `data.category` | String | **Oui** | `UTILITY`, `MARKETING` ou `AUTHENTICATION` (voir les [catégories](/fr/developer-guides/message-templates)). |
| `data.components` | Array | **Oui** | `HEADER`, `BODY`, `FOOTER`, `BUTTONS` (et `CAROUSEL`), au format de Meta. |
| `data.allow_category_change` | Boolean | Non | Permet à Meta de changer la catégorie au lieu de refuser le modèle. |
| `api_provider_instant_id` | String | Non | Votre numéro WhatsApp. Sans ce champ, le numéro WhatsApp de votre entreprise est utilisé ; envoyez-le si vous en avez plusieurs. |

### Composants

| Composant | Règles vérifiées avant l'envoi à Meta |
| :--- | :--- |
| `HEADER` | `format` : `TEXT` (60 caractères max, 1 variable max), `IMAGE` (JPEG/PNG), `VIDEO` (MP4/3GPP), `DOCUMENT` ou `LOCATION`. Un en-tête média demande `example.header_handle`. |
| `BODY` | 1024 caractères max. Variables `{{1}}`, `{{2}}`… numérotées à partir de 1 sans trou, jamais tout au début ni tout à la fin. Une valeur d'exemple par variable dans `example.body_text`. |
| `FOOTER` | 60 caractères max, sans variable. |
| `BUTTONS` | 10 boutons max, texte de 25 caractères max. Voir les [règles des boutons WhatsApp](/fr/developer-guides/message-templates/whatsapp-button-rules). Un bouton `URL` peut avoir une variable, à la fin de l'URL. |

::tip
Digishare vérifie ces règles **avant** d'appeler Meta. Si une règle échoue, vous recevez un `422` qui liste tous les problèmes, et rien n'est envoyé à Meta.
::

### Suivre la validation

Meta répond en quelques minutes, parfois jusqu'à 24 heures. Vous pouvez :

- **Lire le statut** : `GET /v1/api_provider_message_templates/{id}`, champ `status`.
- **Recevoir un webhook** : événement `message_template.status-changed` sur votre [webhook](/fr/developer-guides/webhooks), avec `new_status` et `rejected_reason`.

| `status` | Signification |
| :--- | :--- |
| `draft` | Enregistré, pas envoyé à Meta. |
| `submitted`, `pending` | Meta l'examine. |
| `approved` | Prêt à envoyer. |
| `rejected` | Refusé par Meta : lisez `data.rejected_reason`, corrigez, et soumettez un nouveau modèle. |
| `paused`, `disabled` | Meta l'a arrêté (qualité). |

::api-playground
---
method: GET
url: "https://api.digishare.ma/v1/api_provider_message_templates/{id}"
variables:
  id: "TEMPLATE_ID"
headers:
  Authorization: "Bearer VOTRE_TOKEN"
responseSample:
  data:
    object: "ApiProviderMessageTemplate"
    id: "apmt_x7k2p9"
    name: "order_ready"
    status: "approved"
---
::

### L'utiliser dans une campagne

Quand le statut passe à `approved`, Digishare crée le **modèle de message** pour vous, avec le code `<name>_<language>` (ici `order_ready_fr`). Trouvez son `id`, puis utilisez-le comme `message_template_id` :

```bash
curl "https://api.digishare.ma/v1/message_templates?search=order_ready" \
  -H "Authorization: Bearer VOTRE_TOKEN"
```

## 3. SMS, Telegram et e-mail

Ces canaux ne demandent aucune validation. Créez directement le modèle de message.

::api-playground
---
method: POST
url: "https://api.digishare.ma/v1/message_templates"
headers:
  Authorization: "Bearer VOTRE_TOKEN"
  Content-Type: "application/json"
body:
  title: "Rappel de livraison"
  code: "delivery_reminder"
  template:
    channels:
      sms:
        type: "text"
        content: "Bonjour {{name}}, votre colis arrive demain."
    variables:
      name:
        key: "name"
        type: "text"
responseSample:
  data:
    object: "MessageTemplate"
    id: "mtpl_q8w3e5"
    code: "delivery_reminder"
    title: "Rappel de livraison"
    template:
      channels:
        sms:
          type: "text"
          content: "Bonjour {{name}}, votre colis arrive demain."
---
::

### Champs du corps

| Champ | Type | Requis | Description |
| :--- | :--- | :--- | :--- |
| `title` | String | **Oui** | Nom affiché dans Digishare. |
| `code` | String | Non | Votre propre code unique pour ce modèle. |
| `template.channels` | Object | **Oui** | Une clé par canal : `sms`, `telegram`, `email`. |
| `template.variables` | Object | Non | Les variables du texte, chacune `{ "key": "...", "type": "text" }`. |
| `tags` | Array | Non | Des tags pour classer vos modèles. |

### Une clé par canal

::code-group
```json [SMS]
{
  "channels": {
    "sms": { "type": "text", "content": "Bonjour {{name}}, votre code est {{code}}." }
  },
  "variables": {
    "name": { "key": "name", "type": "text" },
    "code": { "key": "code", "type": "text" }
  }
}
```

```json [Telegram]
{
  "channels": {
    "telegram": { "type": "text", "content": "Bonjour {{name}}, votre commande est prête." }
  },
  "variables": {
    "name": { "key": "name", "type": "text" }
  }
}
```

```json [E-mail]
{
  "channels": {
    "email": { "type": "html", "content": "<p>Bonjour {{name}},</p><p>Votre facture est disponible.</p>" }
  },
  "variables": {
    "name": { "key": "name", "type": "text" }
  }
}
```
::

- Les variables s'écrivent `{{key}}`. La campagne les remplit avec les `variables` de chaque destinataire ou avec `global_data` (voir les [campagnes](/fr/developer-guides/campaigns)).
- **E-mail** : l'objet n'est pas dans le modèle. Il vient de la campagne (son titre par défaut).
- **Telegram** : si un modèle n'a pas de clé `telegram`, une campagne Telegram utilise le texte WhatsApp (`social_media`), jamais le texte SMS.
- Un modèle peut contenir plusieurs canaux (par exemple `sms` et `email`) : le même modèle sert alors pour chaque canal de campagne.

## 4. Erreurs

| Code | Quand | Exemple de message |
| :--- | :--- | :--- |
| `401` | Jeton absent ou invalide | |
| `422` | Le modèle WhatsApp ne respecte pas une règle de Meta | `WhatsApp would reject this template: - Component BODY uses 2 variable(s) but carries no example…` |
| `422` | Meta a refusé le modèle à l'envoi | `<title>: <message> (<developer message>)` (le modèle est enregistré en `rejected`) |
| `400` | Supprimer ou modifier un modèle WhatsApp déjà utilisé | `You cannot delete or update a template that has already been used.` |

::warning
Le `422` liste **tous** les problèmes d'un coup. Corrigez-les tous avant de soumettre à nouveau.
::
