Digishare peut appeler votre serveur quand un de vos modèles de message change. Vous n'avez pas besoin d'interroger l'API sans arrêt.

## 1. S'abonner

::steps

### Ouvrir les paramètres des webhooks

Allez dans **Paramètres Avancés > API Provider** et ouvrez votre fournisseur **Custom Webhooks** (ou créez-en un : voir [Webhooks](/fr/developer-guides/webhooks)).

### Choisir les événements

Dans **Configuration des Webhooks**, ouvrez le groupe **Message Templates** et cliquez sur **+** à côté de l'événement voulu.

### Saisir votre URL

Indiquez l'URL de votre serveur. La méthode `POST` et `application/json` sont les valeurs par défaut. Ajoutez un en-tête ou une auth Basic / Bearer si votre serveur en a besoin.
::

| Événement | Quand |
| :--- | :--- |
| `message_template.status-changed` | Le statut d'un modèle WhatsApp change chez Meta (approuvé, en pause, désactivé…). |
| `message_template.created` | Un modèle de message est créé. |
| `message_template.updated` | Un modèle de message est modifié. |
| `message_template.deleted` | Un modèle de message est supprimé. |
| `message_template.*` | Tous les événements ci-dessus. |

---

## 2. `message_template.status-changed`

```json
{
  "event": "message_template.status-changed",
  "data": {
    "id": "mtpl_q8w3e5",
    "data": {
      "channel": "whatsapp",
      "name": "order_ready",
      "new_status": "paused",
      "language": "fr",
      "rejected_reason": null,
      "other_info": null
    }
  }
}
```

| Champ | Description |
| :--- | :--- |
| `data.id` | L'`id` du modèle de message : celui que vous utilisez comme `message_template_id` dans une campagne. |
| `data.data.channel` | Toujours `whatsapp`. |
| `data.data.name` | Le nom du modèle chez Meta. |
| `data.data.new_status` | Le nouveau statut (voir le tableau ci-dessous). |
| `data.data.language` | La langue du modèle. |
| `data.data.rejected_reason` | La raison de Meta quand le modèle est refusé, sinon `null`. |
| `data.data.other_info` | Des détails en plus de Meta quand il y en a, sinon `null`. |

| `new_status` | Signification | Envoi possible ? |
| :--- | :--- | :--- |
| `approved` | Meta l'a approuvé. | **Oui** |
| `pending` | Meta examine une modification. | Non |
| `rejected` | Meta l'a refusé : lisez `rejected_reason`. | Non |
| `paused` | Meta l'a mis en pause pour qualité faible. Il peut revenir tout seul. | Non |
| `disabled` | Meta l'a désactivé. Créez un nouveau modèle. | Non |
| `system_disabled` | Digishare l'a arrêté car Meta a changé sa catégorie. Vérifiez-le, puis réactivez-le. | Non |

::note
Considérez toute autre valeur comme **non envoyable**.
::

### Quand il est envoyé

- **WhatsApp seulement.** Les modèles SMS, Telegram et e-mail n'ont pas besoin d'approbation.
- **À partir de la première approbation.** Digishare crée le modèle de message quand Meta approuve le modèle WhatsApp. Le webhook est envoyé à partir de là : pauses, désactivations et nouvelles approbations. Avant la première approbation, le modèle de message n'existe pas encore, donc **pas de webhook** : lisez le statut avec `GET /v1/api_provider_message_templates/{id}` (voir [Créer un modèle](/fr/developer-guides/message-templates/create)).
- **Catégorie changée par Meta :** vous recevez `message_template.updated`, avec `template.channels.social_media.whatsapp.status` à `system_disabled`.

## 3. `created`, `updated` et `deleted`

`created` et `updated` envoient le modèle entier. `updated` envoie aussi `changes` : seulement les champs modifiés. `deleted` envoie seulement l'`id`.

```json
{
  "event": "message_template.updated",
  "data": {
    "id": "mtpl_q8w3e5",
    "data": {
      "id": "mtpl_q8w3e5",
      "company_id": "comp_780ew4",
      "message_type_id": "mtyp_r79wde",
      "api_provider_instant_id": "ID_DE_VOTRE_NUMERO_WHATSAPP",
      "code": "order_ready_fr",
      "title": "order_ready (fr)",
      "template": { "channels": { "social_media": { "type": "template" } } },
      "is_template": false,
      "is_used": 1,
      "created_at": "2026-11-27T10:00:00.000000Z",
      "updated_at": "2026-11-27T10:05:00.000000Z"
    },
    "wasRecentlyCreated": false,
    "changes": { "title": "order_ready (fr)" }
  }
}
```

---

## 4. Livraison

- Votre serveur doit répondre avec un statut **2xx** en moins de **30 secondes**.
- Toute autre réponse compte comme un échec. Digishare réessaie **toutes les 5 minutes, jusqu'à 60 fois**.
- Le même événement peut arriver deux fois. Utilisez `data.id` avec `new_status` pour ignorer ceux déjà traités.
- Les requêtes ne sont pas signées. Pour vérifier qu'un appel vient de Digishare, ajoutez un en-tête secret ou une auth Basic / Bearer dans les paramètres du webhook, et vérifiez-le sur votre serveur.
