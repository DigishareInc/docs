Ce document explique comment ajouter des participants à une conversation et comment les retirer.

Les deux endpoints acceptent des tableaux, ce qui permet d'ajouter ou de retirer plusieurs participants en une seule requête. Chaque appel ne se limite pas à mettre à jour la liste des participants : il publie un message système dans le fil, enregistre un évènement `participant`, recalcule les statuts de la conversation et diffuse le changement afin que les clients connectés se mettent à jour en temps réel.

## Ajouter des participants

**Endpoint** : `PUT https://api.digishare.ma/v1/conversations/{id}/attach/participants`

### Paramètres de l'URL

| Paramètre | Type   | Description                          |
| :-------- | :----- | :----------------------------------- |
| `id`      | String | L'ID encodé de la conversation.      |

### Paramètres du Payload

Tous les IDs doivent être fournis sous leur forme encodée.

| Champ   | Type    | Description                                                        |
| :------ | :------ | :----------------------------------------------------------------- |
| `users` | Array   | IDs encodés des utilisateurs à ajouter *(Optionnel)*.              |
| `bots`  | Array   | IDs encodés des chatbots à ajouter *(Optionnel)*.                  |

Renseignez au moins `users` ou `bots`. Les utilisateurs déjà participants sont ignorés : l'appel peut donc être répété sans risque.

::note
L'ajout d'un utilisateur retire le statut `need_agent` et, si aucun bot n'est actif, assigne la conversation à cet utilisateur. Chaque utilisateur ajouté reçoit une notification, sauf lorsqu'un utilisateur s'ajoute lui-même — ce cas est enregistré comme « a rejoint la discussion ».
::

::api-playground
---
method: PUT
url: "https://api.digishare.ma/v1/conversations/0qwylwge5bvmpz65/attach/participants"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
  Content-Type: "application/json"
body:
  users:
    - "780ew4kx3kdyjpa5"
  bots: []
responseSample:
  data:
    object: "Conversation"
    id: "0qwylwge5bvmpz65"
    company_id: "zryw5xlrr8l06bqa"
    code: "CONV-105924"
    status: 1
    human_intervention: 1
    unreadCount: 0
---
::

## Retirer des participants

**Endpoint** : `PUT https://api.digishare.ma/v1/conversations/{id}/detach/participants`

Le payload est identique à celui de l'ajout. Seuls les participants réellement rattachés à la conversation sont retirés ; les IDs inconnus sont ignorés.

| Champ   | Type    | Description                                                        |
| :------ | :------ | :----------------------------------------------------------------- |
| `users` | Array   | IDs encodés des utilisateurs à retirer *(Optionnel)*.              |
| `bots`  | Array   | IDs encodés des chatbots à retirer *(Optionnel)*.                  |

::note
Retirer le dernier utilisateur replace la conversation en `need_agent` : elle retourne donc dans la file des conversations non assignées. Retirer le dernier bot retire le statut `bot_active`.
::

::tip
Un agent peut transmettre son propre ID à cet endpoint pour quitter une conversation. Cela fonctionne sans la permission `detach.chat.room.participants`, tant que l'agent est participant de la conversation.
::

::api-playground
---
method: PUT
url: "https://api.digishare.ma/v1/conversations/0qwylwge5bvmpz65/detach/participants"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
  Content-Type: "application/json"
body:
  users:
    - "780ew4kx3kdyjpa5"
  bots: []
responseSample:
  data:
    object: "Conversation"
    id: "0qwylwge5bvmpz65"
    company_id: "zryw5xlrr8l06bqa"
    code: "CONV-105924"
    status: 1
    human_intervention: 1
    unreadCount: 0
---
::

## Permissions

| Endpoint                      | Permission requise                 | Alternative                                  |
| :---------------------------- | :--------------------------------- | :------------------------------------------- |
| `attach/participants`         | `attach.chat.room.participants`    | —                                            |
| `detach/participants`         | `detach.chat.room.participants`    | Être participant de la conversation          |

::warning
Les deux endpoints utilisent la méthode `PUT`, et non `POST`. Une requête `POST` sur ces chemins renvoie une erreur `405 Method Not Allowed`.
::
