Ce document explique comment ajouter des participants à une conversation et comment les retirer.

Les deux endpoints acceptent des tableaux, ce qui permet d'ajouter ou de retirer plusieurs participants en une seule requête. Chaque appel ne se limite pas à mettre à jour la liste des participants : il publie un message système dans le fil, enregistre un évènement `participant`, recalcule les statuts de la conversation et diffuse le changement afin que les clients connectés se mettent à jour en temps réel.

## Ajouter des participants

**Endpoint** : `PUT https://api.digishare.ma/v1/conversations/{id}/attach/participants`

### Paramètres de l'URL

| Paramètre | Type   | Description                          |
| :-------- | :----- | :----------------------------------- |
| `id`      | String | L'ID encodé de la conversation.      |

### Paramètres du Payload

Tous les IDs doivent être fournis sous leur forme encodée.

| Champ        | Type   | Description                                                                                                  |
| :----------- | :----- | :------------------------------------------------------------------------------------------------------------ |
| `users`      | Array  | IDs encodés des utilisateurs à ajouter *(Optionnel)*.                                                        |
| `bots`       | Array  | IDs encodés des chatbots à ajouter *(Optionnel)*.                                                            |
| `handler_id` | String | ID encodé de l'utilisateur à désigner également comme responsable. Doit figurer dans `users` *(Optionnel)*.   |

Renseignez au moins `users` ou `bots`. Les utilisateurs déjà participants sont ignorés : l'appel peut donc être répété sans risque.

### Participants et responsable

Une conversation compte **plusieurs participants** mais un **seul responsable**. Être participant donne accès à la conversation ; être responsable est ce qui la place dans la file de cet agent.

Ajouter un participant ne retire jamais la conversation à son responsable actuel. Renseignez `handler_id` lorsque le nouvel utilisateur doit également en prendre la charge : l'ancien responsable conserve son accès, mais la conversation quitte sa file.

::note
Sur une conversation qui n'a **pas encore** de responsable, l'ajout d'un utilisateur retire le statut `need_agent` et — si aucun bot n'est actif — lui assigne la conversation : c'est ainsi qu'elle sort de la file non assignée. Chaque utilisateur ajouté reçoit une notification, sauf lorsqu'un utilisateur s'ajoute lui-même — ce cas est enregistré comme « a rejoint la discussion ».
::

::tip
Pour changer de responsable sans toucher à la liste des participants, utilisez `PUT /v1/conversations/{id}/handler/{userId}`. Cet endpoint ajoute l'utilisateur s'il n'est pas encore participant : il fait donc aussi office d'ajout-et-assignation en un seul appel.
::

::api-playground
---
method: PUT
url: "https://api.digishare.ma/v1/conversations/0qwylwge5bvmpz65/attach/participants"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
  Content-Type: "application/json"
body:
  users:
    - "780ew4kx3kdyjpa5"
  bots: []
  handler_id: "780ew4kx3kdyjpa5"
responseSample:
  data:
    object: "Conversation"
    id: "0qwylwge5bvmpz65"
    company_id: "zryw5xlrr8l06bqa"
    code: "CONV-105924"
    status: 1
    human_intervention: 1
    unreadCount: 0
---
::

## Retirer des participants

**Endpoint** : `PUT https://api.digishare.ma/v1/conversations/{id}/detach/participants`

Le payload est identique à celui de l'ajout. Seuls les participants réellement rattachés à la conversation sont retirés ; les IDs inconnus sont ignorés.

| Champ   | Type    | Description                                                        |
| :------ | :------ | :----------------------------------------------------------------- |
| `users` | Array   | IDs encodés des utilisateurs à retirer *(Optionnel)*.              |
| `bots`  | Array   | IDs encodés des chatbots à retirer *(Optionnel)*.                  |

::note
Retirer le dernier utilisateur replace la conversation en `need_agent` : elle retourne donc dans la file des conversations non assignées. Retirer le dernier bot retire le statut `bot_active`.
::

::tip
Un agent peut transmettre son propre ID à cet endpoint pour quitter une conversation. Cela fonctionne sans la permission `detach.chat.room.participants`, tant que l'agent est participant de la conversation.
::

::api-playground
---
method: PUT
url: "https://api.digishare.ma/v1/conversations/0qwylwge5bvmpz65/detach/participants"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
  Content-Type: "application/json"
body:
  users:
    - "780ew4kx3kdyjpa5"
  bots: []
responseSample:
  data:
    object: "Conversation"
    id: "0qwylwge5bvmpz65"
    company_id: "zryw5xlrr8l06bqa"
    code: "CONV-105924"
    status: 1
    human_intervention: 1
    unreadCount: 0
---
::

## Raccourcis pour un seul utilisateur

Lorsqu'un seul participant est concerné, ces deux routes prennent l'utilisateur depuis l'URL au lieu du corps de la requête. Elles s'appuient sur la même logique que les endpoints ci-dessus : le message système, l'évènement, les changements de statut, la notification et la diffusion sont identiques.

| Méthode  | Endpoint                                      | Équivalent à                                          |
| :------- | :-------------------------------------------- | :---------------------------------------------------- |
| `POST`   | `/v1/conversations/{id}/users/{userId}`       | `attach/participants` avec une seule entrée `users`   |
| `DELETE` | `/v1/conversations/{id}/users/{userId}`       | `detach/participants` avec une seule entrée `users`   |

`id` et `userId` doivent être des IDs encodés. Ces routes n'acceptent aucun corps de requête.

Ajoutez `?set_as_handler=1` à la route `POST` pour désigner également cet utilisateur comme responsable — l'équivalent de `handler_id` sur `attach/participants`.

::tip
`DELETE /v1/conversations/{id}/users/{votre_propre_id}` est la manière la plus simple pour un agent de quitter une conversation.
::

::api-playground
---
method: POST
url: "https://api.digishare.ma/v1/conversations/0qwylwge5bvmpz65/users/780ew4kx3kdyjpa5?set_as_handler=1"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
responseSample:
  data:
    object: "Conversation"
    id: "0qwylwge5bvmpz65"
    company_id: "zryw5xlrr8l06bqa"
    code: "CONV-105924"
    status: 1
---
::

::api-playground
---
method: DELETE
url: "https://api.digishare.ma/v1/conversations/0qwylwge5bvmpz65/users/780ew4kx3kdyjpa5"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
responseSample:
  data:
    object: "Conversation"
    id: "0qwylwge5bvmpz65"
    company_id: "zryw5xlrr8l06bqa"
    code: "CONV-105924"
    status: 1
---
::

## Permissions

| Endpoint                                       | Permission requise                 | Alternative                                  |
| :--------------------------------------------- | :--------------------------------- | :------------------------------------------- |
| `attach/participants`, `POST users/{id}`       | `attach.chat.room.participants`    | —                                            |
| `detach/participants`, `DELETE users/{id}`     | `detach.chat.room.participants`    | Être participant de la conversation          |

::warning
Les endpoints `attach/participants` et `detach/participants` utilisent `PUT`, et non `POST`. Seul le raccourci pour un seul utilisateur accepte `POST`, et uniquement sur le chemin `users/{userId}`. Utiliser la mauvaise méthode renvoie une erreur `405 Method Not Allowed`.
::
