---
title: Envoyer un Message
description: "Envoyer un message à un contact avec l'API d'événements : en file d'attente, asynchrone, et la méthode d'envoi recommandée."
---

Envoyez un message d'un Agent (utilisateur système) au contact d'une conversation. La requête est placée dans une file d'attente et reçoit immédiatement un `202 Accepted` ; Digishare crée le message et le livre un instant plus tard. Comme la file absorbe les rafales, c'est la méthode recommandée pour envoyer des messages depuis une intégration.

**Endpoint** : `POST https://api-app.digishare.ma/v1/event/conversation_message`

## Identifier la conversation

Utilisez l'une des deux formes :

- **`conversation_id`** : l'ID provenant d'un [événement webhook](/fr/developer-guides/livechat/integration) ou de [Créer une conversation](/fr/developer-guides/livechat/conversation/create-conversation).
- **`recipient_id` + `channel` + `api_provider_instance_id`** : Digishare retrouve la conversation active du destinataire sur cette instance de fournisseur, ou en crée une. Sans `api_provider_instance_id`, il se contente de chercher une conversation existante.

## Payload

| Champ                      | Type          | Requis   | Description                                                                                                         |
| :------------------------- | :------------ | :------- | :------------------------------------------------------------------------------------------------------------------ |
| `body`                     | String/Object | **Oui**  | Le contenu : une chaîne pour `text` ; un objet pour `location`, `interactive` et les pièces jointes.                |
| `type`                     | String        | Non      | `text` (par défaut), `location`, `interactive`, `image`, `video`, `audio`, `document` ou `sticker`.                 |
| `send_to_third`            | Boolean       | Non      | `true` par défaut : livre au canal du client. `false` enregistre seulement le message dans la conversation.         |
| `conversation_id`          | String        | Non\*    | La conversation dans laquelle écrire.                                                                               |
| `recipient_id`             | String        | Non\*    | Le numéro de téléphone, l'ID WhatsApp ou l'identifiant de plateforme du contact.                                    |
| `channel`                  | String        | Non\*    | Le canal de messagerie (ex : `whatsapp`).                                                                           |
| `api_provider_instance_id` | String        | Non      | L'instance du fournisseur d'API. Nécessaire pour créer une conversation qui n'existe pas encore.                    |
| `event_type`               | String        | Non      | `conversation_message`. Déjà présent dans l'URL : vous pouvez l'omettre ou le répéter ici.                          |

\* Envoyez `conversation_id`, ou `recipient_id` **et** `channel`.

::note
Le body de chaque type de message est le même que sur l'[API Messages](/fr/developer-guides/livechat/outgoing-messages/text_message). Pour envoyer une image, une vidéo, un fichier audio ou un document, passez un lien dans `body` : voir [Pièces jointes](/fr/developer-guides/livechat/outgoing-messages/attachments). L'objet `file` et `reply_to` ne sont pas pris en charge ici ; utilisez `POST /v1/messages` pour cela.
::

::warning
**Protection des 24 Heures** : Si le temps écoulé depuis le dernier message entrant dépasse 24 heures (ex : la fenêtre du service client sur WhatsApp), l'envoi de messages peut être restreint par votre fournisseur.
::

::api-playground
---
method: POST
url: "https://api-app.digishare.ma/v1/event/conversation_message"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
  Content-Type: "application/json"
body:
  event_type: "conversation_message"
  channel: "whatsapp"
  type: "text"
  send_to_third: true
  api_provider_instance_id: "<ID_INSTANCE_FOURNISSEUR>"
  recipient_id: "<NUMERO_DESTINATAIRE>"
  body: "Corps du Message"
responseSample:
  event_id: "2633736349319958528"
  status: "accepted"
  timestamp: "2026-02-12T14:22:23.133414141Z"
---
::

Le même message avec un ID de conversation :

```json
{
  "conversation_id": "VOTRE_ID_CONVERSATION",
  "type": "text",
  "send_to_third": true,
  "body": "Corps du Message"
}
```

## Réponse

`202 Accepted` signifie que l'événement a été **mis en file d'attente**, pas que le message a été créé ou livré.

| Champ       | Description                                         |
| :---------- | :-------------------------------------------------- |
| `event_id`  | ID de cet événement.                                |
| `status`    | `accepted`.                                         |
| `timestamp` | Moment où l'événement a été accepté.                |

L'`event_id` est enregistré sur le message une fois celui-ci créé. Utilisez-le pour relier votre requête au message : il est renvoyé sous le nom `event_id` par `GET /v1/conversations/{id}/messages` et dans les webhooks `live_chat.new_message`.

Si Digishare ne parvient pas à résoudre la conversation, ou si l'expéditeur n'en est pas participant, le message n'est pas créé même si la requête a été acceptée.

### Erreurs

| HTTP  | `error`                | Signification                                                                                                     |
| :---- | :--------------------- | :---------------------------------------------------------------------------------------------------------------- |
| `400` | `invalid_json`         | Le corps de la requête n'est pas du JSON valide.                                                                  |
| `400` | `validation_failed`    | `body` est absent, ou ni `conversation_id` ni `recipient_id` + `channel` ne sont fournis. Voir `details`.         |
| `413` | `payload_too_large`    | L'événement dépasse 1 Mo.                                                                                         |
| `503` | `service_unavailable`  | La file est temporairement indisponible. Réessayez après les `retry_after` secondes indiquées dans la réponse.    |

## Qui envoie le message

Le message est publié au nom de l'utilisateur de votre jeton d'accès. Cet utilisateur doit être participant de la conversation ; sinon Digishare se rabat sur le premier agent de la conversation, et ne crée aucun message s'il n'y en a pas.
