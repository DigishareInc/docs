---
title: Envoyer un Message
description: "Envoyer un message à un contact avec l'API d'événements : en file d'attente, asynchrone, et la méthode d'envoi recommandée."
---

Envoyez un message d'un Agent (utilisateur système) au contact d'une conversation. La requête est placée dans une file d'attente et reçoit immédiatement un `202 Accepted` ; Digishare crée le message et le livre un instant plus tard. Comme la file absorbe les rafales, c'est la méthode recommandée pour envoyer des messages depuis une intégration.

**Endpoint** : `POST https://api-app.digishare.ma/v1/event/conversation_message`

## Identifier la conversation

Utilisez l'une des deux formes :

- **`conversation_id`** : l'ID provenant d'un [événement webhook](/fr/developer-guides/livechat/integration).
- **`recipient_id` + `channel` + `api_provider_instance_id`** : Digishare retrouve la conversation active du destinataire sur cette instance de fournisseur, ou en crée une. Sans `api_provider_instance_id`, il se contente de chercher une conversation existante.

## Payload

| Champ                      | Type          | Requis   | Description                                                                                                         |
| :------------------------- | :------------ | :------- | :------------------------------------------------------------------------------------------------------------------ |
| `body`                     | String/Object | **Oui**  | Le contenu : une chaîne pour `text` ; un objet pour `location`, `interactive` et les pièces jointes.                |
| `type`                     | String        | Non      | `text` (par défaut), `location`, `interactive`, `image`, `video`, `audio`, `document` ou `sticker`.                 |
| `send_to_third`            | Boolean       | Non      | `true` par défaut : livre au canal du client. `false` enregistre seulement le message dans la conversation.         |
| `conversation_id`          | String        | Non\*    | La conversation dans laquelle écrire.                                                                               |
| `recipient_id`             | String        | Non\*    | Le numéro de téléphone, l'ID WhatsApp ou l'identifiant de plateforme du contact.                                    |
| `channel`                  | String        | Non\*    | Le canal de messagerie (ex : `whatsapp`).                                                                           |
| `api_provider_instance_id` | String        | Non      | L'instance du fournisseur d'API. Nécessaire pour créer une conversation qui n'existe pas encore.                    |
| `event_type`               | String        | Non      | `conversation_message`. Déjà présent dans l'URL : vous pouvez l'omettre ou le répéter ici.                          |

\* Envoyez `conversation_id`, ou `recipient_id` **et** `channel`.

::note
Le `body` de chaque type de message est décrit dans [Messages Sortants](/fr/developer-guides/livechat/outgoing-messages/text_message). Pour envoyer une image, une vidéo, un fichier audio ou un document, passez un lien dans `body` (voir [Pièces jointes](/fr/developer-guides/livechat/outgoing-messages/attachments)) ou, pour un petit fichier, envoyez-le dans `file` (voir [Envoyer un fichier](#envoyer-un-fichier-base64)).
::

::warning
**Protection des 24 Heures** : Si le temps écoulé depuis le dernier message entrant dépasse 24 heures (ex : la fenêtre du service client sur WhatsApp), l'envoi de messages peut être restreint par votre fournisseur.
::

::api-playground
---
method: POST
url: "https://api-app.digishare.ma/v1/event/conversation_message"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
  Content-Type: "application/json"
body:
  event_type: "conversation_message"
  channel: "whatsapp"
  type: "text"
  send_to_third: true
  api_provider_instance_id: "<ID_INSTANCE_FOURNISSEUR>"
  recipient_id: "<NUMERO_DESTINATAIRE>"
  body: "Corps du Message"
responseSample:
  event_id: "2633736349319958528"
  status: "accepted"
  timestamp: "2026-02-12T14:22:23.133414141Z"
---
::

Le même message avec un ID de conversation :

```json
{
  "conversation_id": "VOTRE_ID_CONVERSATION",
  "type": "text",
  "send_to_third": true,
  "body": "Corps du Message"
}
```

## Envoyer un fichier (base64)

Envoyez un petit fichier dans `file`. Digishare le conserve, l'affiche dans l'inbox et le livre comme n'importe quelle pièce jointe : voir [Pièces jointes](/fr/developer-guides/livechat/outgoing-messages/attachments). Le type (image, vidéo, audio, document) est détecté à partir du contenu.

| Champ            | Type   | Requis  | Description                                                                                                                                           |
| :--------------- | :----- | :------ | :---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `file.base64`    | String | **Oui** | Le fichier encodé en base64. Un préfixe `data:...;base64,` est accepté.                                                                               |
| `file.file_name` | String | Non     | Le nom affiché avec le fichier. Lettres, chiffres, espaces, `_` et `-` sont conservés ; les points deviennent `_`. L'extension vient toujours du type détecté. |
| `file.caption`   | String | Non     | Texte envoyé dans le même message que le fichier (images, vidéos et documents). Sans lui, un `body` non vide sert de légende.                         |
| `file.extension` | String | Non     | Uniquement pour les fichiers Office dont le contenu n'indique pas le type : `docx`, `xlsx`, `pptx`, `doc`, `xls` ou `ppt`.                            |

```json
{
  "conversation_id": "VOTRE_ID_CONVERSATION",
  "body": "",
  "file": {
    "base64": "JVBERi0xLjQKJ...",
    "file_name": "devis-2026-001.pdf",
    "caption": "Votre devis"
  }
}
```

- **Taille** : l'événement entier est limité à 1 Mo, donc le fichier lui-même peut faire environ **700 Ko**. Au-delà, [envoyez un lien](/fr/developer-guides/livechat/outgoing-messages/attachments#envoi-par-lien) : WhatsApp récupère lui-même le fichier, et Digishare n'impose aucune limite de taille.
- **Types autorisés** : PDF ; images JPEG, PNG, WebP et GIF ; vidéos MP4 et 3GP ; audio OGG, MP3, M4A, AAC et AMR ; DOC, DOCX, XLS, XLSX, PPT et PPTX ; TXT et CSV. C'est le contenu qui décide, pas le nom : un script, une page web, un SVG ou un exécutable renommé en `.pdf` est refusé.
- **`body` et `type`** : `body` reste requis par l'endpoint, envoyez donc `""` si vous n'avez pas de légende. Avec un fichier, `type` est ignoré.

::warning
Le fichier est vérifié **après** l'acceptation de l'événement. S'il est refusé (type non autorisé, base64 invalide, trop volumineux), vous avez quand même reçu `202` mais aucun message n'est créé et rien n'est livré. Vérifiez le fichier de votre côté avant l'envoi.
::

### Exemple complet : un PDF avec une légende

Envoie un PDF de moins de 700 Ko environ avec une légende.

```bash
curl -X POST "https://api-app.digishare.ma/v1/event/conversation_message" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "conversation_id": "YOUR_CONVERSATION_ID",
    "body": "",
    "file": {
      "file_name": "quote.pdf",
      "caption": "Votre devis, valable jusqu’au 31 octobre",
      "base64": "JVBERi0xLjQK..."
    }
  }'
```

`base64` est le fichier encodé sans retour à la ligne : `base64 -w0 quote.pdf` (sur macOS : `base64 -i quote.pdf`). Un vrai PDF est bien plus long que cet exemple, et une ligne de commande ne peut pas dépasser environ 128 Ko : pour un fichier plus gros, enregistrez le JSON dans un fichier et envoyez-le avec `--data-binary @message.json`.

Réponse `202 Accepted` :

```json
{
  "event_id": "2719257001409384448",
  "status": "accepted",
  "timestamp": "2026-10-06T14:10:55.489438969Z"
}
```

## Réponse

`202 Accepted` signifie que l'événement a été **mis en file d'attente**, pas que le message a été créé ou livré.

| Champ       | Description                                         |
| :---------- | :-------------------------------------------------- |
| `event_id`  | ID de cet événement.                                |
| `status`    | `accepted`.                                         |
| `timestamp` | Moment où l'événement a été accepté.                |

L'`event_id` est enregistré sur le message une fois celui-ci créé. Utilisez-le pour relier votre requête au message : il est renvoyé sous le nom `event_id` par `GET /v1/conversations/{id}/messages` et dans les webhooks `live_chat.new_message`.

Si Digishare ne parvient pas à résoudre la conversation, ou si l'expéditeur n'en est pas participant, le message n'est pas créé même si la requête a été acceptée.

### Erreurs

| HTTP  | `error`                | Signification                                                                                                     |
| :---- | :--------------------- | :---------------------------------------------------------------------------------------------------------------- |
| `401` | `unauthorized`         | L'en-tête `Authorization` est absent, ou n'a pas la forme `Bearer <token>`.                                       |
| `403` | `forbidden`            | Le jeton d'accès est invalide ou a expiré. Voir `details`.                                                        |
| `403` | `Access Denied`        | Votre adresse IP est **bloquée**. Voir [Si vous recevez « Access Denied »](#si-vous-recevez--access-denied-).     |
| `404` | `Not Found`            | Le chemin n'existe pas. Les événements vont sur `POST /v1/event/{type}`.                                          |
| `400` | `invalid_json`         | Le corps de la requête n'est pas du JSON valide.                                                                  |
| `400` | `validation_failed`    | `body` est absent, ou ni `conversation_id` ni `recipient_id` + `channel` ne sont fournis. Voir `details`.         |
| `413` | `payload_too_large`    | L'événement dépasse 1 Mo. Avec un fichier base64, cela fait environ 700 Ko de fichier.                            |
| `503` | `service_unavailable`  | La file est temporairement indisponible. Réessayez après les `retry_after` secondes indiquées dans la réponse.    |

### Si vous recevez « Access Denied »

Un `403 Access Denied` ne vient **ni de votre jeton ni de votre payload** : votre adresse IP a été **bloquée**. Digishare bloque une adresse qui envoie des requêtes répétées vers des chemins qui n'existent pas, ce qui protège le service des scanners. Par défaut, 5 requêtes de ce type en 10 minutes suffisent, et le blocage dure 24 heures.

Causes fréquentes :

- **Une mauvaise URL.** Le seul chemin pour les événements est `POST https://api-app.digishare.ma/v1/event/{type}`. Tout le reste (`/v1/messages`, `/api/...`, une faute de frappe) répond `404 Not Found` et compte pour le blocage.
- **Autre chose sur la même IP** qui appelle d'autres chemins : une sonde de supervision, un test de santé, un scanner, ou une autre application derrière la même adresse sortante.

Que faire :

1. Corrigez l'URL, et empêchez tout autre programme de cette adresse d'appeler d'autres chemins.
2. Contactez le support Digishare avec votre **adresse IP sortante** et l'heure du premier `403`. Le support lève le blocage.

Ne relancez pas en boucle : une adresse bloquée reste bloquée.

## Qui envoie le message

Le message est publié au nom de l'utilisateur de votre jeton d'accès. Cet utilisateur doit être participant de la conversation ; sinon Digishare se rabat sur le premier agent de la conversation, et ne crée aucun message s'il n'y en a pas.
