L'API asynchrone accepte une campagne sous forme d'événement sur `api-app.digishare.ma` et répond dès que l'événement est en file. La plateforme crée ensuite la campagne en arrière-plan, avec les mêmes règles que l'API Campagnes standard. Utilisez-la pour les intégrations à grand volume qui n'ont pas besoin de la campagne créée dans la réponse.

::note
**Prérequis** :

- Un **Bearer Token** valide, le même que sur `api.digishare.ma` (voir [Authentification](/fr/developer-guides/authentication)).
- Une charge utile de campagne qui fonctionne avec `POST https://api.digishare.ma/v1/campaigns`.
::

## Standard ou Asynchrone

Les deux endpoints acceptent la même charge utile et créent la même campagne. Ils diffèrent par ce qu'ils renvoient et par la taille qu'ils acceptent.

| | API standard | API asynchrone |
| :--- | :--- | :--- |
| **Endpoint** | `POST https://api.digishare.ma/v1/campaigns` | `POST https://api-app.digishare.ma/v1/event/campaign` |
| **Réponse** | La campagne créée | `202 Accepted` avec un `event_id` |
| **Erreurs métier** (modèle, expéditeur, solde) | Renvoyées dans la réponse | Non renvoyées : l'événement est rejeté en arrière-plan |
| **Taille de la charge utile** | Grandes charges utiles, fichiers base64 compris | Environ 1 Mo par événement |

::tip
Construisez et testez votre charge utile avec l'API standard d'abord, car elle renvoie chaque erreur immédiatement. Passez à l'endpoint asynchrone une fois la charge utile stable.
::

## Endpoint

**Endpoint** : `POST https://api-app.digishare.ma/v1/event/campaign`

Le corps est le même objet JSON que pour l'API Campagnes standard. Consultez [Campagnes WhatsApp](/fr/developer-guides/campaigns/whatsapp) et [Campagnes SMS](/fr/developer-guides/campaigns/sms) pour la liste complète des champs.

La passerelle vérifie les règles suivantes avant d'accepter l'événement :

| Champ | Règle |
| :--- | :--- |
| `title` | **Requis**. Au moins 3 caractères. |
| `channel` | **Requis**. Une chaîne comme `whatsapp` ou `sms`. |
| `message_template_id` | **Requis**, sauf si la charge utile contient un `message_template` en ligne. |
| `recipients` | Doit être un tableau s'il est présent. |

::important
La campagne appartient toujours à l'entreprise du propriétaire du token. L'API ignore tout `company_id` envoyé dans la charge utile.
::

## Exemple

La requête suivante met en file une campagne WhatsApp personnalisée et définit un `external_ref` pour la suivre ensuite :

::api-playground
---
method: POST
url: https://api-app.digishare.ma/v1/event/campaign
description: Mettre en file une campagne WhatsApp pour une création en arrière-plan.
variables:
  token: VOTRE_TOKEN
  senderId: VOTRE_ID_EXPEDITEUR
  templateId: VOTRE_ID_MODELE
headers:
  Authorization: Bearer {token}
  Content-Type: application/json
body:
  title: Campagne de notification de commande
  channel: whatsapp
  sender_label_id: "{senderId}"
  message_template_id: "{templateId}"
  external_ref: ORDER-BATCH-2026-09-24
  notify_webhooks: true
  global_data:
    name: "%recipient.name%"
    order_id: "%recipient.order_id%"
  recipients:
    - wa_id: "212600000000"
      name: John
      order_id: ORD-123
    - wa_id: "212600000001"
      name: Jane
      order_id: ORD-456
responseSample:
  event_id: acme2633736349319958528
  timestamp: "2026-09-24T10:15:02.133414141Z"
  status: accepted
---
::

## Réponses

### Accepté

Une réponse `202` signifie que l'événement est en file. La campagne n'existe pas encore à ce stade.

```json
{
  "event_id": "acme2633736349319958528",
  "timestamp": "2026-09-24T10:15:02.133414141Z",
  "status": "accepted"
}
```

Conservez l'`event_id`. L'équipe support l'utilise pour retracer ce qui est arrivé à votre campagne.

### Erreurs

Chaque réponse d'erreur contient un code `error` et un `status`. Une `400` liste aussi chaque problème dans `details`.

| Statut | `error` | Signification | Que faire |
| :--- | :--- | :--- | :--- |
| `400` | `invalid_json` | Le corps n'est pas un JSON valide. | Corrigez le corps JSON. |
| `400` | `validation_failed` | Une règle du tableau ci-dessus n'est pas respectée. | Corrigez la charge utile. Renvoyer la même charge utile échoue à nouveau. |
| `401` | `unauthorized` | L'en-tête `Authorization` est absent ou mal formé. | Envoyez `Authorization: Bearer <token>`. |
| `403` | `forbidden` | Le token est invalide, révoqué ou expiré. | Utilisez un token valide. Un token tout juste créé peut mettre quelques secondes à être accepté. |
| `413` | `payload_too_large` | L'événement dépasse environ 1 Mo. | Répartissez les destinataires sur plusieurs événements, ou envoyez les médias par URL plutôt qu'en base64. |
| `429` | `rate_limit_exceeded` | Trop d'événements dans la fenêtre en cours. | Attendez `retry_after` secondes. Les en-têtes `X-RateLimit-*` indiquent votre quota. |
| `503` | `service_unavailable` | La file est temporairement indisponible. | Réessayez après `retry_after` secondes. |

## Suivre la Campagne

L'API asynchrone ne renvoie pas la campagne : vous la retrouvez grâce à votre propre référence.

1. Renseignez `external_ref` avec un identifiant de votre système.
2. Définissez `notify_webhooks` sur `true`.
3. Faites correspondre le champ `campaign_external_ref` des [webhooks de campagne](/fr/developer-guides/webhooks) à votre identifiant.

La campagne apparaît aussi dans votre dashboard Digishare, avec la source `API`.

Quand le traitement en arrière-plan rejette un événement, par exemple à cause d'un modèle inconnu, d'un sender label qui n'appartient pas à votre entreprise ou d'un solde insuffisant, la plateforme ne crée aucune campagne et n'envoie aucun webhook. Contactez le support avec l'`event_id` pour connaître la raison exacte.

::warning
Seuls les endpoints `/v1/event/...` existent sur `api-app.digishare.ma`. Gardez tous les autres appels, comme `/v1/oauth/token` ou `/v1/campaigns`, sur `api.digishare.ma` : les requêtes vers des chemins inconnus sur `api-app.digishare.ma` renvoient `404`, et leur répétition fait bloquer l'adresse IP appelante.
::
