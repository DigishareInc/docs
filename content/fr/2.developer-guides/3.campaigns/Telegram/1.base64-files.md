---

Ce guide explique comment envoyer une campagne Telegram avec un fichier encodé en **base64** directement dans votre requête API. Vous n'avez besoin ni d'une URL publique ni d'un envoi séparé du fichier.

::note
**Prérequis** :
- Un **Bearer Token** valide dans l'en-tête Authorization.
- Un **expéditeur Telegram** (votre bot).
- Un **modèle de message** avec un message fichier sur Telegram dont le fichier est une variable, par exemple `{{facture}}`.
- Le `telegram_id` de chaque destinataire. La personne doit d'abord avoir appuyé sur **Démarrer** dans votre bot.
::

## 1. Fonctionnement

1. Dans le créateur de modèles, ajoutez un message fichier sur le canal Telegram et choisissez **A different file per contact (variable)**. Utilisez une variable comme `{{facture}}`.
2. Dans votre requête, choisissez un nom de placeholder, par exemple `PLACEHOLDER_INVOICE`.
3. Dans `global_data`, donnez à la variable un objet qui pointe vers ce placeholder :
   ```json
   "facture": {
     "provider": "digishare",
     "id": "PLACEHOLDER_INVOICE"
   }
   ```
4. Placez le fichier sous le même nom de placeholder dans `base64_files`.
5. Digishare enregistre le fichier, remplace le placeholder, et le bot envoie le fichier à chaque destinataire.

::warning
L'`id` doit être dans cet objet. Une simple chaîne comme `"facture": "PLACEHOLDER_INVOICE"` ne fonctionne pas : le message échoue avec `failed_file_not_found`.
::

## 2. Implémentation API

::api-playground
---
method: POST
url: https://api.digishare.ma/v1/campaigns
description: Créer une campagne Telegram avec un fichier base64 intégré.
variables:
  token: YOUR_TOKEN
  senderId: YOUR_SENDER_ID
  templateId: YOUR_TEMPLATE_ID
headers:
  Authorization: Bearer {token}
  Content-Type: application/json
body:
  title: Envoi des factures
  channel: telegram
  sender_label_id: "{senderId}"
  message_template_id: "{templateId}"
  global_data:
    telegram_id: "%recipient.telegram_id%"
    facture:
      provider: "digishare"
      id: "PLACEHOLDER_INVOICE"
  recipients:
    - telegram_id: "123456789"
  base64_files:
    PLACEHOLDER_INVOICE:
      base64: "data:application/pdf;base64,JVBERi0xLjQK..."
      file_name: "facture_12345"
      extension: "pdf"
---
::

## 3. Champs de configuration

L'objet `base64_files` est une table. Chaque clé est votre placeholder, et chaque valeur est un objet :

| Champ | Type | Statut | Description |
| :--- | :--- | :--- | :--- |
| `base64` | `string` | **Requis** | Le fichier encodé en base64. Il peut commencer par le préfixe Data URI. |
| `file_name` | `string` | Optionnel | Le nom du fichier, sans l'extension. |
| `extension` | `string` | Optionnel | L'extension du fichier (ex. `pdf`, `png`, `jpg`). |

## 4. Bon à savoir

- **Un fichier pour tous.** Avec le placeholder dans `global_data`, tous les destinataires reçoivent le même fichier.
- **La légende** du message fichier peut utiliser des variables, comme `Bonjour {{prenom}}`.

## 5. Un fichier différent pour chaque destinataire

Une campagne peut envoyer à chaque destinataire son propre fichier. Donnez à chaque fichier son placeholder dans `base64_files`, et reliez chaque destinataire à son fichier :

```json
{
  "global_data": {
    "telegram_id": "%recipient.telegram_id%",
    "facture": "%recipient.facture%"
  },
  "recipients": [
    { "telegram_id": "123456789", "facture": { "provider": "digishare", "id": "INVOICE_A" } },
    { "telegram_id": "987654321", "facture": { "provider": "digishare", "id": "INVOICE_B" } }
  ],
  "base64_files": {
    "INVOICE_A": { "base64": "data:application/pdf;base64,JVBERi0xLjQK...", "file_name": "invoice_a", "extension": "pdf" },
    "INVOICE_B": { "base64": "data:application/pdf;base64,JVBERi0xLjQK...", "file_name": "invoice_b", "extension": "pdf" }
  }
}
```
