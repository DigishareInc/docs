A **message template** is the message a campaign sends. You create it once, then you use its `id` as `message_template_id` when you [create a campaign](/en/developer-guides/campaigns).

All requests need a [Bearer token](/en/developer-guides/authentication). The company comes from your token.

## 1. Which call for which channel

| Channel | Call | Meta approval | When can you use it |
| :--- | :--- | :--- | :--- |
| **WhatsApp (template)** | `POST /v1/api_provider_message_templates` | **Yes** (minutes to 24 h) | When `status` is `approved`: Digishare then creates the message template for you |
| **SMS** | `POST /v1/message_templates` | No | Right away |
| **Telegram** | `POST /v1/message_templates` | No | Right away |
| **E-mail** | `POST /v1/message_templates` | No | Right away |

::note
A WhatsApp **template** is the only message you can send to a contact who has not written to you in the last 24 hours. Inside the 24-hour window, a free WhatsApp message (text, image, buttons) needs no approval.
::

## 2. WhatsApp: submit a template to Meta

You send the template in Meta's format. Digishare passes it to Meta through your WhatsApp number.

::api-playground
---
method: POST
url: "https://api.digishare.ma/v1/api_provider_message_templates"
headers:
  Authorization: "Bearer YOUR_TOKEN"
  Content-Type: "application/json"
body:
  channel_code: "whatsapp"
  name: "order_ready"
  external_id: "order_ready"
  status: "submit"
  data:
    name: "order_ready"
    language: "fr"
    category: "UTILITY"
    components:
      - type: "BODY"
        text: "Bonjour {{1}}, votre commande {{2}} est prête."
        example:
          body_text:
            - ["Sara", "A-1042"]
      - type: "FOOTER"
        text: "Atlas Store"
      - type: "BUTTONS"
        buttons:
          - type: "QUICK_REPLY"
            text: "Merci"
responseSample:
  data:
    object: "ApiProviderMessageTemplate"
    id: "apmt_x7k2p9"
    api_provider_instant_id: "YOUR_WHATSAPP_NUMBER_ID"
    external_id: "order_ready"
    channel_code: "whatsapp"
    name: "order_ready"
    status: "submitted"
    data:
      name: "order_ready"
      language: "fr"
      category: "UTILITY"
---
::

### Body fields

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `channel_code` | String | **Yes** | Always `whatsapp`. |
| `name` | String | **Yes** | Template name: lowercase letters, digits and `_` only. |
| `external_id` | String | **Yes** | Same value as `name`. |
| `status` | String | **Yes** | `submit` sends it to Meta now. `draft` only saves it. |
| `data.name` | String | **Yes** | Same value as `name`. |
| `data.language` | String | **Yes** | Language code, for example `fr`, `en`, `ar`. |
| `data.category` | String | **Yes** | `UTILITY`, `MARKETING` or `AUTHENTICATION` (see [categories](/en/developer-guides/message-templates)). |
| `data.components` | Array | **Yes** | `HEADER`, `BODY`, `FOOTER`, `BUTTONS` (and `CAROUSEL`), in Meta's format. |
| `data.allow_category_change` | Boolean | No | Lets Meta change the category instead of rejecting the template. |
| `api_provider_instant_id` | String | No | Your WhatsApp number. Leave it out to use your company's WhatsApp number; send it when you have several. |

### Components

| Component | Rules checked before sending to Meta |
| :--- | :--- |
| `HEADER` | `format`: `TEXT` (max 60 characters, max 1 variable), `IMAGE` (JPEG/PNG), `VIDEO` (MP4/3GPP), `DOCUMENT` or `LOCATION`. A media header needs `example.header_handle`. |
| `BODY` | Max 1024 characters. Variables `{{1}}`, `{{2}}`… numbered from 1 with no gap, never at the very start or end. One example value per variable in `example.body_text`. |
| `FOOTER` | Max 60 characters, no variable. |
| `BUTTONS` | Max 10 buttons, text max 25 characters. See [WhatsApp button rules](/en/developer-guides/message-templates/whatsapp-button-rules). A `URL` button can have one variable, at the end of the URL. |

::tip
Digishare checks these rules **before** calling Meta. If one fails, you get a `422` listing every problem, and nothing is sent to Meta.
::

### Follow the approval

Meta answers in a few minutes, sometimes up to 24 hours. You can:

- **Read the status**: `GET /v1/api_provider_message_templates/{id}`, field `status`.
- **Receive a webhook**: `message_template.status-changed`, from the first approval on (pauses, disables…). Before that, read the status. See [Template webhooks](/en/developer-guides/message-templates/webhooks).

| `status` | Meaning |
| :--- | :--- |
| `draft` | Saved, not sent to Meta. |
| `submitted`, `pending` | Meta is reviewing it. |
| `approved` | Ready to send. |
| `rejected` | Refused by Meta: read `data.rejected_reason`, fix, and submit a new template. |
| `paused`, `disabled` | Meta stopped it (quality). |

::api-playground
---
method: GET
url: "https://api.digishare.ma/v1/api_provider_message_templates/{id}"
variables:
  id: "TEMPLATE_ID"
headers:
  Authorization: "Bearer YOUR_TOKEN"
responseSample:
  data:
    object: "ApiProviderMessageTemplate"
    id: "apmt_x7k2p9"
    name: "order_ready"
    status: "approved"
---
::

### Use it in a campaign

When the status becomes `approved`, Digishare creates the **message template** for you, with the code `<name>_<language>` (here `order_ready_fr`). Find its `id`, then use it as `message_template_id`:

```bash
curl "https://api.digishare.ma/v1/message_templates?search=order_ready" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## 3. SMS, Telegram and e-mail

These channels need no approval. Create the message template directly.

::api-playground
---
method: POST
url: "https://api.digishare.ma/v1/message_templates"
headers:
  Authorization: "Bearer YOUR_TOKEN"
  Content-Type: "application/json"
body:
  title: "Delivery reminder"
  code: "delivery_reminder"
  template:
    channels:
      sms:
        type: "text"
        content: "Bonjour {{name}}, votre colis arrive demain."
    variables:
      name:
        key: "name"
        type: "text"
responseSample:
  data:
    object: "MessageTemplate"
    id: "mtpl_q8w3e5"
    code: "delivery_reminder"
    title: "Delivery reminder"
    template:
      channels:
        sms:
          type: "text"
          content: "Bonjour {{name}}, votre colis arrive demain."
---
::

### Body fields

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `title` | String | **Yes** | Name shown in Digishare. |
| `code` | String | No | Your own unique code for this template. |
| `template.channels` | Object | **Yes** | One key per channel: `sms`, `telegram`, `email`. |
| `template.variables` | Object | No | The variables used in the text, each `{ "key": "...", "type": "text" }`. |
| `tags` | Array | No | Tags to sort your templates. |

### One key per channel

::code-group
```json [SMS]
{
  "channels": {
    "sms": { "type": "text", "content": "Bonjour {{name}}, votre code est {{code}}." }
  },
  "variables": {
    "name": { "key": "name", "type": "text" },
    "code": { "key": "code", "type": "text" }
  }
}
```

```json [Telegram]
{
  "channels": {
    "telegram": { "type": "text", "content": "Bonjour {{name}}, votre commande est prête." }
  },
  "variables": {
    "name": { "key": "name", "type": "text" }
  }
}
```

```json [E-mail]
{
  "channels": {
    "email": { "type": "html", "content": "<p>Bonjour {{name}},</p><p>Votre facture est disponible.</p>" }
  },
  "variables": {
    "name": { "key": "name", "type": "text" }
  }
}
```
::

- Variables are written `{{key}}`. The campaign fills them from each recipient's `variables` or from `global_data` (see [campaigns](/en/developer-guides/campaigns)).
- **E-mail**: the subject is not in the template. It comes from the campaign (its title by default).
- **Telegram**: if a template has no `telegram` key, a Telegram campaign uses the WhatsApp text (`social_media`), never the SMS text.
- One template can hold several channels (for example `sms` and `email`), so the same template works for each campaign channel.

## 4. Errors

| Code | When | Example message |
| :--- | :--- | :--- |
| `401` | Missing or wrong token | |
| `422` | The WhatsApp template breaks a Meta rule | `WhatsApp would reject this template: - Component BODY uses 2 variable(s) but carries no example…` |
| `422` | Meta refused the template on submit | `<title>: <message> (<developer message>)` (the template is saved as `rejected`) |
| `400` | Delete or change a WhatsApp template already used | `You cannot delete or update a template that has already been used.` |

::warning
The `422` lists **every** problem at once. Fix them all before you submit again.
::
