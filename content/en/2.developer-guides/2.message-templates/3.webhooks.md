Digishare can call your server when one of your message templates changes. You do not need to ask the API again and again.

## 1. Subscribe

::steps

### Open the webhook settings

Go to **Advanced Settings > API Provider** and open your **Custom Webhooks** provider (or create one: see [Webhooks](/en/developer-guides/webhooks)).

### Pick the events

In **Webhook Configuration**, open the **Message Templates** group and click **+** next to the event you want.

### Enter your URL

Give your endpoint URL. Method `POST` and `application/json` are the defaults. Add a header or Basic / Bearer auth if your server needs one.
::

| Event | When |
| :--- | :--- |
| `message_template.status-changed` | The status of a WhatsApp template changes at Meta (approved, paused, disabled…). |
| `message_template.created` | A message template is created. |
| `message_template.updated` | A message template is changed. |
| `message_template.deleted` | A message template is deleted. |
| `message_template.*` | All the events above. |

---

## 2. `message_template.status-changed`

```json
{
  "event": "message_template.status-changed",
  "data": {
    "id": "mtpl_q8w3e5",
    "data": {
      "channel": "whatsapp",
      "name": "order_ready",
      "new_status": "paused",
      "language": "fr",
      "rejected_reason": null,
      "other_info": null
    }
  }
}
```

| Field | Description |
| :--- | :--- |
| `data.id` | The message template `id`: the one you use as `message_template_id` in a campaign. |
| `data.data.channel` | Always `whatsapp`. |
| `data.data.name` | The template name at Meta. |
| `data.data.new_status` | The new status (see the table below). |
| `data.data.language` | The template language. |
| `data.data.rejected_reason` | Meta's reason when the template is rejected, else `null`. |
| `data.data.other_info` | Extra details from Meta when there are some, else `null`. |

| `new_status` | Meaning | Can you send it? |
| :--- | :--- | :--- |
| `approved` | Meta approved it. | **Yes** |
| `pending` | Meta is reviewing a change. | No |
| `rejected` | Meta refused it: read `rejected_reason`. | No |
| `paused` | Meta paused it because of low quality. It can come back by itself. | No |
| `disabled` | Meta disabled it. Create a new template. | No |
| `system_disabled` | Digishare stopped it because Meta changed its category. Check it, then turn it on again. | No |

::note
Treat any other value as **not sendable**.
::

### When it is sent

- **WhatsApp only.** SMS, Telegram and e-mail templates need no approval.
- **From the first approval on.** Digishare creates the message template when Meta approves the WhatsApp template. The webhook is sent from then on: later pauses, disables and re-approvals. Before the first approval, there is no message template yet, so **no webhook**: read the status with `GET /v1/api_provider_message_templates/{id}` (see [Create a template](/en/developer-guides/message-templates/create)).
- **Category changed by Meta:** you get `message_template.updated`, with `template.channels.social_media.whatsapp.status` set to `system_disabled`.

## 3. `created`, `updated` and `deleted`

`created` and `updated` send the whole template. `updated` also sends `changes`: only the fields that changed. `deleted` sends only the `id`.

```json
{
  "event": "message_template.updated",
  "data": {
    "id": "mtpl_q8w3e5",
    "data": {
      "id": "mtpl_q8w3e5",
      "company_id": "comp_780ew4",
      "message_type_id": "mtyp_r79wde",
      "api_provider_instant_id": "YOUR_WHATSAPP_NUMBER_ID",
      "code": "order_ready_fr",
      "title": "order_ready (fr)",
      "template": { "channels": { "social_media": { "type": "template" } } },
      "is_template": false,
      "is_used": 1,
      "created_at": "2026-11-27T10:00:00.000000Z",
      "updated_at": "2026-11-27T10:05:00.000000Z"
    },
    "wasRecentlyCreated": false,
    "changes": { "title": "order_ready (fr)" }
  }
}
```

---

## 4. Delivery

- Your server must answer with a **2xx** status within **30 seconds**.
- Any other answer counts as a failure. Digishare tries again **every 5 minutes, up to 60 times**.
- The same event can reach you twice. Use `data.id` with `new_status` to skip the ones you already handled.
- Requests are not signed. To check that a call comes from Digishare, add a secret header or Basic / Bearer auth in the webhook settings, and check it on your server.
