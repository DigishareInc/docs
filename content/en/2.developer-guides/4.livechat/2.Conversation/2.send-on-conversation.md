Send a message from an Agent (system user) to the contact in a conversation. The request is placed in a queue and answered immediately with `202 Accepted`; Digishare creates the message and delivers it moments later. Because the queue absorbs bursts, this is the recommended way to send messages from an integration.

**Endpoint**: `POST https://api-app.digishare.ma/v1/event/conversation_message`

## Identify the conversation

Use one of the two forms:

- **`conversation_id`**: the ID from a [webhook event](/developer-guides/livechat/integration).
- **`recipient_id` + `channel` + `api_provider_instance_id`**: Digishare finds the recipient's active conversation on that provider instance, or creates one. Without `api_provider_instance_id` it only looks for an existing conversation.

## Payload

| Field                      | Type          | Required | Description                                                                                                         |
| :------------------------- | :------------ | :------- | :------------------------------------------------------------------------------------------------------------------ |
| `body`                     | String/Object | **Yes**  | The content: a string for `text`; an object for `location`, `interactive` and attachments.                          |
| `type`                     | String        | No       | `text` (default), `location`, `interactive`, `image`, `video`, `audio`, `document` or `sticker`.                    |
| `send_to_third`            | Boolean       | No       | Defaults to `true`: deliver to the customer's platform. `false` only records the message in the conversation.       |
| `conversation_id`          | String        | No\*     | The conversation to write to.                                                                                       |
| `recipient_id`             | String        | No\*     | The phone number, WhatsApp ID or platform identifier of the contact.                                                |
| `channel`                  | String        | No\*     | The messaging channel (e.g. `whatsapp`).                                                                            |
| `api_provider_instance_id` | String        | No       | The API provider instance. Needed to create a conversation that does not exist yet.                                 |
| `event_type`               | String        | No       | `conversation_message`. Already part of the URL, so you can omit it or repeat it here.                              |

\* Send `conversation_id`, or `recipient_id` **and** `channel`.

::note
The `body` of each message type is described under [Outgoing Messages](/developer-guides/livechat/outgoing-messages/text_message). To send an image, video, audio file or document, pass a link in `body` (see [Attachments](/developer-guides/livechat/outgoing-messages/attachments)) or, for a small file, send it in `file` (see [Send a file](#send-a-file-base64)).
::

::warning
**24-Hour Guard**: If the elapsed time since the last inbound message exceeds 24 hours (e.g., WhatsApp's customer service window), delivery may be restricted by your provider.
::

::api-playground
---
method: POST
url: "https://api-app.digishare.ma/v1/event/conversation_message"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
  Content-Type: "application/json"
body:
  event_type: "conversation_message"
  channel: "whatsapp"
  type: "text"
  send_to_third: true
  api_provider_instance_id: "<PROVIDER_INSTANCE_ID>"
  recipient_id: "<RECIPIENT_PHONE_NUMBER>"
  body: "Message Body"
responseSample:
  event_id: "2633736349319958528"
  status: "accepted"
  timestamp: "2026-02-12T14:22:23.133414141Z"
---
::

The same message with a conversation ID:

```json
{
  "conversation_id": "YOUR_CONVERSATION_ID",
  "type": "text",
  "send_to_third": true,
  "body": "Message Body"
}
```

## Send a file (base64)

Send a small file in `file`. Digishare stores it, shows it in the inbox and delivers it like any other attachment: see [Attachments](/developer-guides/livechat/outgoing-messages/attachments). The type (image, video, audio, document) is detected from the content.

| Field            | Type   | Required | Description                                                                                                                                    |
| :--------------- | :----- | :------- | :--------------------------------------------------------------------------------------------------------------------------------------------- |
| `file.base64`    | String | **Yes** | The file, base64-encoded. A `data:...;base64,` prefix is accepted.                                                                             |
| `file.file_name` | String | No       | The name shown with the file. Letters, digits, spaces, `_` and `-` are kept; dots become `_`. The extension always comes from the detected type. |
| `file.caption`   | String | No       | Text sent in the same message as the file (images, videos and documents). If you omit it, a non-empty `body` is used as the caption.            |
| `file.extension` | String | No       | Only for Office files whose content does not say which kind they are: `docx`, `xlsx`, `pptx`, `doc`, `xls` or `ppt`.                           |

```json
{
  "conversation_id": "YOUR_CONVERSATION_ID",
  "body": "",
  "file": {
    "base64": "JVBERi0xLjQKJ...",
    "file_name": "quote-2026-001.pdf",
    "caption": "Your quote"
  }
}
```

- **Size**: the whole event is limited to 1 MB, so the file itself can be about **700 KB**. For anything larger, [send a link](/developer-guides/livechat/outgoing-messages/attachments#send-by-link): WhatsApp fetches the file itself, and Digishare puts no size limit on it.
- **Allowed types**: PDF; JPEG, PNG, WebP and GIF images; MP4 and 3GP video; OGG, MP3, M4A, AAC and AMR audio; DOC, DOCX, XLS, XLSX, PPT and PPTX; TXT and CSV. The content decides, not the name: a script, web page, SVG or executable renamed to `.pdf` is refused.
- **`body` and `type`**: `body` is still required by the endpoint, so send `""` when you have no caption. With a file, `type` is ignored.

::warning
The file is checked **after** the event is accepted. If it is refused (type not allowed, invalid base64, too large), you still received `202` but no message is created and nothing is delivered. Check the file on your side before sending.
::

### Full example: a PDF with a caption

Sends a PDF of under about 700 KB with a caption.

```bash
curl -X POST "https://api-app.digishare.ma/v1/event/conversation_message" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "conversation_id": "YOUR_CONVERSATION_ID",
    "body": "",
    "file": {
      "file_name": "quote.pdf",
      "caption": "Your quote, valid until 31 October",
      "base64": "JVBERi0xLjQK..."
    }
  }'
```

`base64` is the file encoded without line breaks: `base64 -w0 quote.pdf` (on macOS: `base64 -i quote.pdf`). A real PDF is much longer than this example, and a command line cannot hold more than about 128 KB: for a bigger file, save the JSON to a file and send it with `--data-binary @message.json`.

Response `202 Accepted`:

```json
{
  "event_id": "2719257001409384448",
  "status": "accepted",
  "timestamp": "2026-10-06T14:10:55.489438969Z"
}
```

## Response

`202 Accepted` means the event was **queued**, not that the message was created or delivered.

| Field       | Description                                         |
| :---------- | :-------------------------------------------------- |
| `event_id`  | ID of this event.                                   |
| `status`    | `accepted`.                                         |
| `timestamp` | When the event was accepted.                        |

The `event_id` is saved on the message once it is created. Use it to match your request to the message: it is returned as `event_id` by `GET /v1/conversations/{id}/messages` and in `live_chat.new_message` webhooks.

If Digishare cannot resolve the conversation, or the sender is not a participant of it, the message is not created even though the request was accepted.

### Errors

| HTTP  | `error`                | Meaning                                                                                                           |
| :---- | :--------------------- | :---------------------------------------------------------------------------------------------------------------- |
| `401` | `unauthorized`         | The `Authorization` header is missing, or is not in the form `Bearer <token>`.                                    |
| `403` | `forbidden`            | The access token is invalid or has expired. See `details`.                                                        |
| `403` | `Access Denied`        | Your IP address is **blocked**. See [If you get "Access Denied"](#if-you-get-access-denied).                      |
| `404` | `Not Found`            | The path does not exist. Events go to `POST /v1/event/{type}`.                                                    |
| `400` | `invalid_json`         | The body is not valid JSON.                                                                                       |
| `400` | `validation_failed`    | `body` is missing, or neither `conversation_id` nor `recipient_id` + `channel` is given. See `details`.           |
| `413` | `payload_too_large`    | The event is larger than 1 MB. With a base64 file, that is about 700 KB of file.                                  |
| `503` | `service_unavailable`  | The queue is temporarily unavailable. Retry after the `retry_after` seconds in the response.                      |

### If you get "Access Denied"

`403 Access Denied` does **not** come from your token or your payload: it means your IP address has been **blocked**. Digishare blocks an address that makes repeated requests to paths that do not exist, which protects the service from scanners. By default, 5 such requests within 10 minutes are enough, and the block lasts 24 hours.

Common causes:

- **A wrong URL.** The only path for events is `POST https://api-app.digishare.ma/v1/event/{type}`. Anything else (`/v1/messages`, `/api/...`, a typo) answers `404 Not Found` and counts toward the block.
- **Something else on the same IP** calling other paths: a monitoring probe, a health check, a scanner, or another application behind the same outgoing address.

What to do:

1. Fix the URL, and stop anything else on that address from calling other paths.
2. Contact Digishare support with your **outgoing IP address** and the time of the first `403`. Support lifts the block.

Do not retry in a loop: a blocked address stays blocked.

## Who sends the message

The message is posted as the user of your access token. That user should be a participant of the conversation; otherwise Digishare falls back to the conversation's first agent, and creates no message if there is none.
