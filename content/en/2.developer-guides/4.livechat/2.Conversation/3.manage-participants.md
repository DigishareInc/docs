This document explains how to add participants to a conversation and how to remove them.

Both endpoints accept arrays, so you can add or remove several participants in a single request. Each call does more than update the participant list: it posts a system message into the thread, records a `participant` chat event, recalculates the room statuses, and broadcasts the change so connected clients update in real time.

## Add participants

**Endpoint**: `PUT https://api.digishare.ma/v1/conversations/{id}/attach/participants`

### Path Parameters

| Parameter | Type   | Description                              |
| :-------- | :----- | :--------------------------------------- |
| `id`      | String | The encoded ID of the conversation.      |

### Body Parameters

All IDs must be provided in their encoded format.

| Field   | Type  | Description                                                        |
| :------ | :---- | :----------------------------------------------------------------- |
| `users` | Array | Encoded user IDs to add as participants *(Optional)*.              |
| `bots`  | Array | Encoded chatbot IDs to add as participants *(Optional)*.           |

Send at least one of `users` or `bots`. Users that already participate in the conversation are ignored, so the call is safe to repeat.

::note
Adding a user clears the `need_agent` status and, when no bot is active, assigns the conversation to that user. Every added user receives a notification, except when a user adds themselves — that case is recorded as "joined the discussion" instead.
::

::api-playground
---
method: PUT
url: "https://api.digishare.ma/v1/conversations/0qwylwge5bvmpz65/attach/participants"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
  Content-Type: "application/json"
body:
  users:
    - "780ew4kx3kdyjpa5"
  bots: []
responseSample:
  data:
    object: "Conversation"
    id: "0qwylwge5bvmpz65"
    company_id: "zryw5xlrr8l06bqa"
    code: "CONV-105924"
    status: 1
    human_intervention: 1
    unreadCount: 0
---
::

## Remove participants

**Endpoint**: `PUT https://api.digishare.ma/v1/conversations/{id}/detach/participants`

The body is identical to the add endpoint. Only participants that currently belong to the conversation are removed; unknown IDs are ignored.

| Field   | Type  | Description                                                        |
| :------ | :---- | :----------------------------------------------------------------- |
| `users` | Array | Encoded user IDs to remove *(Optional)*.                           |
| `bots`  | Array | Encoded chatbot IDs to remove *(Optional)*.                        |

::note
Removing the last remaining user sets the conversation back to `need_agent`, so it returns to the unassigned queue. Removing the last bot clears the `bot_active` status.
::

::tip
An agent can pass their own ID to this endpoint to leave a conversation. This works without the `detach.chat.room.participants` permission, as long as the agent is a participant.
::

::api-playground
---
method: PUT
url: "https://api.digishare.ma/v1/conversations/0qwylwge5bvmpz65/detach/participants"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
  Content-Type: "application/json"
body:
  users:
    - "780ew4kx3kdyjpa5"
  bots: []
responseSample:
  data:
    object: "Conversation"
    id: "0qwylwge5bvmpz65"
    company_id: "zryw5xlrr8l06bqa"
    code: "CONV-105924"
    status: 1
    human_intervention: 1
    unreadCount: 0
---
::

## Single-user shortcuts

When you only need to change one participant, these two routes take the user from the URL instead of a request body. They delegate to the same logic as the endpoints above, so the system message, chat event, status changes, notification and broadcast are identical.

| Method   | Endpoint                                      | Equivalent to                                    |
| :------- | :-------------------------------------------- | :----------------------------------------------- |
| `POST`   | `/v1/conversations/{id}/users/{userId}`       | `attach/participants` with a single `users` entry |
| `DELETE` | `/v1/conversations/{id}/users/{userId}`       | `detach/participants` with a single `users` entry |

Both `id` and `userId` must be encoded IDs. Neither route takes a body.

::tip
`DELETE /v1/conversations/{id}/users/{your_own_id}` is the simplest way for an agent to leave a conversation.
::

::api-playground
---
method: POST
url: "https://api.digishare.ma/v1/conversations/0qwylwge5bvmpz65/users/780ew4kx3kdyjpa5"
headers:
  Authorization: "Bearer <JWT_TOKEN>"
responseSample:
  data:
    object: "Conversation"
    id: "0qwylwge5bvmpz65"
    company_id: "zryw5xlrr8l06bqa"
    code: "CONV-105924"
    status: 1
---
::

## Permissions

| Endpoint                                   | Required permission                | Alternative                          |
| :----------------------------------------- | :--------------------------------- | :----------------------------------- |
| `attach/participants`, `POST users/{id}`   | `attach.chat.room.participants`    | —                                    |
| `detach/participants`, `DELETE users/{id}` | `detach.chat.room.participants`    | Being a participant of the conversation |

::warning
The `attach/participants` and `detach/participants` endpoints use `PUT`, not `POST`. Only the single-user shortcut accepts `POST`, and only on the `users/{userId}` path. Using the wrong method returns a `405 Method Not Allowed`.
::
