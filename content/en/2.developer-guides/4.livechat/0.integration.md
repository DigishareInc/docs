This guide outlines the technical integration with the Digishare LiveChat system. The integration is bidirectional:

1.  **Webhooks**: Your system listens for real-time events (New Conversations, Incoming Messages).
2.  **Event API**: Your system sends replies back to the user with a single `POST` that Digishare queues and answers at once.

::note
Ensure you have your **Access Token** ready. See [Authentication](/developer-guides/authentication) for details.
::

## 1. Webhooks

Your system must expose a **POST** endpoint to receive event payloads from Digishare.

### Events

::accordion
::accordion-item{label="New Conversation" icon="i-mdi-plus"}
**Event**: `live_chat.new_conversation`

Triggered when a user initiates a new conversation. Use the `data.id` (Conversation ID) to send replies.

**Payload:**

```json
{
  "event": "live_chat.new_conversation",
  "data": {
    "id": "YOUR_CONVERSATION_ID",
    "data": {
      "created_at": "2025-12-03T12:28:50.000000Z",
      "third": {
        "id": "YOUR_THIRD_ID",
        "name": "Adil Chbada"
      }
    }
  }
}
```

::

::accordion-item{label="Incoming Message" icon="i-mdi-arrow-bottom-left"}
**Event**: `live_chat.new_message`

Triggered when a customer sends a message. `type` tells you how to read `body`: a string for `text`, an object for locations, buttons and media. See [Incoming Messages](/developer-guides/livechat/incoming-messages/constraints).

**Payload:**

```json
{
  "event": "live_chat.new_message",
  "data": {
    "id": "YOUR_MESSAGE_ID",
    "data": {
      "conversation_id": "YOUR_CONVERSATION_ID",
      "type": "text",
      "body": "/info",
      "sender": {
        "model_type": "third",
        "name": "Adil Chbada"
      }
    }
  }
}
```

::
::

## 2. Sending Messages

Send messages with the **Event API**: it queues your message and answers in milliseconds, so bursts of messages do not overload your integration or Digishare. For a detailed reference on every message type (text, location, interactive, attachments), see [Outgoing Messages](/developer-guides/livechat/outgoing-messages/text_message), including [Attachments](/developer-guides/livechat/outgoing-messages/attachments) for images, videos, audio files and documents.

### Event API

Send a message and get a `202 Accepted` back. See [Send on Conversation](/developer-guides/livechat/conversation/send-on-conversation) for every field.

**Endpoint**: `POST https://api-app.digishare.ma/v1/event/conversation_message`

::api-playground
---
method: POST
url: "https://api-app.digishare.ma/v1/event/conversation_message"
headers:
  Authorization: "Bearer YOUR_TOKEN"
  Content-Type: "application/json"
body:
  event_type: "conversation_message"
  conversation_id: "YOUR_CONVERSATION_ID"
  type: "text"
  send_to_third: true
  body: "Hello! How can I help you?"
responseSample:
  event_id: "2633736349319958528"
  status: "accepted"
  timestamp: "2026-10-02T20:55:33.894921622Z"
---
::

You can address the conversation with `conversation_id`, or with `recipient_id` + `channel` + `api_provider_instance_id`: Digishare then finds the customer's active conversation, or creates one. The `202` answer means the event was queued; keep its `event_id` to find the message later.
